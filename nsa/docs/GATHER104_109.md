## Design and negative controls

Existing v050-v055, v102-v108 and v152-v168 experiments had covered block
loads, gather threads, Q fragments, probability shared layout, late
normalization, manual reductions and V prefetch. They were inspected before
this round. The new variants isolate FP32-to-FP16 conversion and K/V swizzle.

| Probe | Change relative to NSA103 | Decision |
|---|---|---|
| NSA104 | local FP32 copy, scalar half conversion, explicit probability fragment, shared P copy | retain S2 only |
| NSA105 | analogous scalar conversion for staged S4 output | no reliable final-file benefit |
| NSA106 | K/V shared swizzle vecSize4 | reject: slower |
| NSA107 | K/V shared swizzle vecSize16 | reject: S4 slower, S2 near parity |
| NSA108 | combine S2 probability and long-S4 output changes | correct in tested cases; S4 gain too small |
| NSA109 | keep only S2 probability change, inherit all NSA103 paths otherwise | final-file checks PASS; recommend user OJ validation |

New factories use only TileLang APIs. No input/output cache, external device
implementation, async copy, pipeline or custom compiler option was added.
Existing math, KD, threads128, masks, normalization timing and automatic
synchronization are unchanged. Scalar conversion intentionally changes the
conversion expression, not the FP32 normalization or destination values.
