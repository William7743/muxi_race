## Controlled changes

- NSA130:128 D128/BS32 scheduler only, causal block-ID predicate and bounded
  modulo identity for aligned blocks; remove redundant V load fallbacks.
- NSA131:128 D128/BS16 warp-sync factory only, same bounds transformation.
- NSA132:130 first-V tile stored as8 local uint32 words per lane, then
  reinterpreted into shared half values.128-thread mapping covers32x64 once.
- NSA133:128 packed-V control without130's bounded index; retain later-V
  fallback. First-V fallback is redundant on the unchanged aligned dispatcher.

AST audits constrain all edits to the stated factory. Math, tile sizes, threads,
GEMM, synchronization, dispatcher and compiler pass flags remain unchanged.
No extra V tile is prefetched. T.Ramp/T.reinterpret/T.unroll/T.vectorized are
TileLang expressions; no external C++, async transfer or pipeline is introduced.
Static checks cover all2048 packed elements exactly once and65536 half bit
patterns. Bounds audit covers1723/3453 transition checks, not arbitrary-invalid
input guarantees. Correctness evidence uses contiguous FP16 and int32 inputs.

## Compiler evidence and limits

Library paths/hashes were captured from the actual compiled callable. Exported
CUDA hashes match measured rows. Extraction hashes the library before/after and
does not edit caches. Source, runtime library, embedded IR and device-text hashes
are bound together in nsa130_133_verification.json.

130 introduces `%6 = alloca [16 x %struct.__half], align 2, addrspace(5)` plus
private memcpy uses: a32-byte temporary absent from128.132/133 packed storage
removes these private-IR matches and largely recovers130's lost time, but remains
slower than128. This supports a compiler-storage explanation, not a measured
runtime spill count or a complete causal attribution: no new hardware-counter
capture was performed for these versions.131 has no such private-IR matches
but its smaller generated source does not give a reproducible speedup.

The initial132 extraction assumed all libraries lived in persistent cache;
first-JIT132/133 actually used `/tmp/*.so`. That diagnostic failed before their
extraction, not during GPU validation. The failure log and completed128 extraction
remain archived. New inspect_library_ir.py takes captured source/library hashes
and supports these runtime paths; it refuses overwrites. Resumed132/133 extraction
completed successfully, with no recompile or GPU rerun. Partial local tar is not
the evidence source; only the completed bundle populated the committed outputs.
