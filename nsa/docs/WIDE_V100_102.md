# D64 wide V loads followed by register layout conversion

Parent: NSA097. Tests use the replacement C500 16 GB sGPU, not the unavailable
full 64 GB GPU. This is a local experiment, not an OJ score.

## Hypothesis and scope

External v206-v212 had already tested direct MMA-fragment V loads. Those
removed shared V but generated 16 scalar half loads per lane and regressed.
This experiment asks whether contiguous global loads plus explicit register
redistribution can avoid that problem. Only the D64/G16/BS16 S1 path that
previously selected `nsa_simplified_k_fragment` is changed. Other factories,
math and dispatch are preserved except the explicit new factory selection.
The initial target is case8 (B2/L4096/H1/HQ16).

## Experiments

- NSA100 annotates a contiguous `[16,64]` fragment with thread=`i*4+j//16`
  and index=`j%16`, then copies to the PV MMA fragment. Compilation fails in
  LayoutInference with `Layout infer conflict between Vlinear and Vs`.
  Python syntax and the bijective layout audit pass, but neither is a GPU pass.
  The zero-row timing file is intentional: compilation prevented measurements.
- NSA101 loads four contiguous halves per lane and column tile into local
  registers; packs half pairs as uint32; performs explicit TileLang shuffles;
  extracts the original half bits into the MMA B layout. The host simulation
  verifies all 1024 half positions. One target reference check passes for each
  parent/candidate, and all six timing samples pass both guard gates.
  Raw medians: NSA097 40.80128us, NSA101 52.97664us. Guard-relative elapsed
  time is 1.294612, i.e. about29.5% slower. No promotion.
- Generated NSA101 source confirms four uint2 global V reads per lane and
  32 uint32 shuffles per lane (two sites inside four-by-four unrolled loops).
  V shared traffic is removed, but the redistribution costs outweigh it in this
  measured implementation. This does not prove all possible register transposes
  are inferior.
- Source inspection also exposed that `T.shfl_sync(..., width=64)` leaves a
  default mask of `0xffffffff` widened to uint64. Width does not change the mask.
  NSA102 explicitly supplies `0xffffffffffffffff` to both shuffle sites so the
  conclusion does not rely on unspecified upper-lane participation. NSA101 is
  retained as a diagnostic artifact, not a submission candidate.
- NSA102's full-mask run (seed137/current) passes the target reference check,
  with its paired parent also passing. All6 timing samples are qualified.
  NSA097 40.58624us versus NSA102 52.85376us; guard-relative elapsed time
  1.299661, about30.0% slower. The explicit-mask implementation also fails
  the performance gate, so the wide-V/shuffle route is closed for now.

## Reproduction and evidence

`tests/audit_nsa100.py` and `tests/audit_nsa101.py` perform source isolation,
layout coordinate/bit simulations, literal module-assignment checks and the
NSA102 mask-only diff check. They do not run the OJ SafeExecutor.

`results/2026-09-09/nsa100.log`, `nsa101.log`, `nsa101.jsonl`,
`nsa101_summary.json` and `sources101/` preserve raw failure/timing/generated
source evidence. Compilation and benchmark execution are ordinary local
TileLang operations; no external implementation, asynchronous copy, result
cache, or OJ submission was added by these experiments.

The NSA102 run is recorded in `nsa102.jsonl`, `nsa102_summary.json`, and the
initial portion of `nsa103_full.log`; generated source is `sources103/nsa102_case8.cu`.

Benchmark: pinned external `tests/calibrate_oj_protocol.py`, cupti, seed0/public,
three alternating rounds; guard v159 before/after each sample; warmup10,
repeat50, cache flush256000000 bytes. Strict gates: guard drift<=3%, absolute
guard ratio0.92..1.08, at least two usable samples per implementation.
