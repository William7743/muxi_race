# NSA119/120: disjoint max/sum workspaces

2026-09-09. Standalone children of NSA109; no OJ submission or score claim.

## Hypothesis and scope

The installed MACA reduction template implements cross-warp offset64 by a
pre-write CTA barrier, workspace write, post-write barrier, then peer read.
NSA109 invokes this twice (max,sum) using aliased workspace. The pre-write
sum barrier protects outstanding max reads. NSA119 instead assigns max and
sum distinct halves of a single shared float[2,128] buffer, preserving the
global-max-stabilized softmax and offset64/32/16 reduction routing. It removes
that one pre-sum-write barrier. NSA120 is identical but retains the barrier,
isolating synchronization from manual reduction/code-generation effects.

This is not older v037/v041 partitioned softmax: no extra exponentials or
partial-softmax renormalization are introduced. No externally injected device
implementation, async copy, result cache, custom compilation flags or input
hardcoding. TileLang shuffles explicitly specify full64-bit masks and width64.

Only nsa_d128_scheduler changes; original dispatch, QK/PV, prefetch, causal
mask, scalar probability/output conversion, and writeback remain in place.
The local max expression is reassociated; numerical equivalence still requires
runtime checking. Source files stay immutable once measured.

## Static and generated-source checks completed

Both compile successfully. AST audit and128-lane routing simulation pass:
each lane's final reduction includes the32 score columns for its G16 row.
Generated case6 CUDA places reduce_pair at byte0, max at[0,512),sum at[512,1024),
Vs at byte1024. The halves do not overlap with each other or live Vs storage.
The pre-max CTA barrier protects completed QK reads before aliased Ks storage
is reused. Post-write barriers publish both halves. Existing pre-probability
CTA barrier protects completed sum reads before acc_cast reuses byte0.
119/120 generated sources differ by exactly one __syncthreads before sum write.
These are source-level/routing checks, not hardware race instrumentation or
proof for all shapes/compiler versions. Both code and masks are verified before
GPU numerical screening.
