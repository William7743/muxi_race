## Design and correctness

Four D64/S1/G16/BS16 factories stage sixteen FP32 accumulator elements in a
thread-local array, convert each to FP16, then write the same shared output
buffer. Global output copy, barriers, dispatcher and other math remain unchanged
at TileLang source level. `audit_nsa098.py` and `audit_nsa099.py` restore these
edits and compare parent AST. Syntax and bounded source-isolation checks pass;
this does not prove a thread-private array is routed to the correct shared address.

NSA098 used `T.Parallel(G,D)` for the private-half-to-shared store. The first
target (point2, B1/L128/H1/G16/D64/S1/BS16) failed:120178/131072 mismatches,
maximum absolute difference3.626953125. Measurement stopped before recording
any timings. `nsa098.jsonl` is intentionally empty; the failure is in `nsa098.log`.
This is an actual numerical failure, unlike the earlier OJ module-loader failure.

Generated case2 confirms wrong routing. For lane0, NSA098 writes the same first
four half registers to shared rows0/4/8/12. The parent's lane0 should write row0,
columns0/16/32/48 from four different register groups. Source-level same-shaped
loops do not imply the same lane layout when reading a thread-local buffer.

NSA099 explicitly uses shared coordinates:

```text
row = lane % 16
column = chunk * 16 + (lane // 16) * 4 + element
register = chunk * 4 + element
```

Enumerating64 lanes×4 chunks×4 elements covers all1024 shared half positions
exactly once. Saved case2 generated code matches this map and preserves uint2
shared stores and the parent's uint4 global output copy. Source exports for
097/098/099 are under `results/2026-09-09/sources099/`.
