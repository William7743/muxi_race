## Experiments

All versions preserve NSA123's validated plain-factory case5 optimization.
No math, TileLang synchronization, tile, thread count, output conversion,
result reuse, async transfer, external device implementation or toolchain edit.

- NSA124 removes the plain-factory workload>=4096 restriction, retaining
  S1/D64/G16/BS16/aligned-length conditions. Its additional formal cases are
  2,4,14. This tests benefit at smaller query grids.
- NSA125 adds two bounded clones from NSA122, V-prefetch and K-fragment+
  V-prefetch, moving the Q shared load after K loading, before mask setup.
  Only aligned D64/G16/BS16/S1 workloads>=4096 use these two new paths.
- NSA126 is the same Q-placement change without bounded addresses, a control.
  Older v186 already explored K-before-Q and was not retained on these
  prefetch routes.126 is a fresh control, not a newly invented optimization.
  The new question is the interaction with NSA122's bounded addressing.
- NSA127 combines125 with plain bounded-load dispatch at workload>=1024.
  The smallest additional case2 had no reliable benefit and keeps123.
  The existing parent factory selection remains authoritative; conditions
  are ordinary shape dispatch, not evaluation-stage or testcase-order logic.

During construction an exact-copy assertion detected that the non-prefetch
K-fragment factory already had conditional Q ordering. No partial files/job
were created by that failed builder attempt. That factory was excluded from
the new order experiment;125/126 target only formal7/9, not8.

The aligned-block range/sentinel reasoning is inherited from D64_122_123.md.
Q/K loads both precede the existing warp barrier and GEMM. The original block
guard is uniform across each CTA; no barrier becomes divergent within a warp.
This is a source-level lifetime argument, not a hardware race-tool result.
