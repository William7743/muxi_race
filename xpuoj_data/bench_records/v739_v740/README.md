# v739/v740：恢复晚 barrier 的短程预取，负结果归档

2026-09-05。两版完整随机输出均通过与 v720 的精度比较，但同窗入口计时均 **0 胜 4 负**，
不推荐 OJ。v739 比同窗 v737 回升，却仍慢于 v720；不能写成超过当前基线。
本批没有新 OJ ID，也没有将 trace 时间混入下面的入口样本。

## 隔离设计

- [v739](../../probe_v739_v737_e32_stage2_short_up_late_barrier.py) 基于 v737：
  `A3 → next-Up fragment → MMA3 → barrier → fragment 写 Up → Down copy`。
- [v740](../../probe_v740_v738_e32_stage2_short_down_late_barrier.py) 基于 v738：
  `A3 → next-Down fragment → MMA3 → barrier → Up copy → fragment 写 Down`。

两版只把父版显式早 barrier 移回 MMA3 后，预取仍在 MMA3 前；没有新增 buffer，
仍保持 Up→Down shared 写入顺序。与旧 v667/v671 的区别依旧是：旧版在 ki0 前预取、
片段跨全部四次 MMA，新版只跨最后一次 MMA。

目标仍仅 `E32/H7168/I2048`、unsplit M128×N128×K64、256 threads、32 KiB shared。
原 v720 builders、Stage1、其他 shape、terminal、数学、raw/padded 语义保持不变；
独立 probe 不覆盖 `submission.py`，每次当前输入完整重算，仍是两次 kernel launch。
无 async/BSM/pipeline、外部计算或结果复用。

## 随机测试边界

[完整随机入口原始日志](codex_e32_720_737_739_740_random_entry.log)包含四候选：
v720、v737、v739、v740。本地 C500、TileLang 0.1.10+maca，E32/H7168/I2048；
`alternating64-220` 是本地 fixture，不是已核验的 OJ 路由数据。
4544 valid / 6144 padded 行、48 个 M 块。

固定种子为 `DEFAULT_SEED + case_id = 20260903`，**同一批随机输入三轮复算**，
不是三个随机种子。每轮先将 workspace/out 污染为 NaN，完整 `launch_full` 及真实
`run_kernel` 的日志均打印 `max_abs=0.000000, bad=0/44040192`；参考为同批 v720
输出，非独立官方 golden。判据为有限值及 `abs(diff) <= 0.05 + 0.05*abs(ref)`；
`max_abs` 只打印六位小数，没有额外 bitwise 相等检查，不能据此宣称逐位完全相同。
本节随机验证没有增加其他输入集；[独立常量 trace](../v736_v738/PROFILING.md)
不混入以下入口样本。

`warmup=1, iters=1, rounds=4`，正／反／正／反序；以下全为完整 **entry** 计时，
不把它叫作 Stage2 单独时间。初始化、编译、NaN 污染与精度检查不计入这些样本。

## 生成代码与风险

[CPU 审计](audit_v739_v740_cpu.py)和 Ruff 通过：全源码/AST 仅允许 barrier 移动与
新 builder 命名、分派；K=1..129、256、513 标签生命周期与边界、两种 route dtype、
新输入两次 launch、缓存与非目标分派通过。测试不等于证明机器代码全部安全。

[生成原始日志](codex_e32_739_740_codegen.log)和[完整生成代码审计](CODEGEN_AUDIT.md)
确认父版到新版整个生成 C++ 也只移动一条显式 barrier。额外自动同步**没有减少**：
v739 保留 4 个静态 site，MMA3 后是连续两条同步；v740 保留 5 个，包括 Up 写回后的
额外同步。正行 K32 的生成 C++ 调用次数仍为 94/95，v720 是 63；这不是硬件计数，
未检查下游 ISA 是否合并连续同步。shared、片段尺寸及 uint4 读/uint2 写均与父版一致。
不能据源数组或 null 资源字段断言物理寄存器、spill 或唯一性能原因。

生成的 float32 尾部 epilogue 仍在行有效判断前读取未 clamp 的 raw route weight。
最终 expert 的 padding 可能越界读取，空 raw 数组不因此安全；没有加入 v723 bounds
修复。三轮随机精度比较通过不消除这一继承风险，也不证明其他 route dtype 的 lowering 安全。
