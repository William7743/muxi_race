# v727–v729：E32 Stage1 微调度实验（含相邻 v730 组合复测）

记录日期：2026-09-05。本文件保存无 tracer 的本地随机输入检查与完整 entry 计时样本；profiling 数据另行追加，不与以下样本混算。

当前结论：第二种 routing fixture 已使 v727 的表现转为负向，它不具备跨 fixture 的稳健收益，**不优先提交 OJ，仅保留结构实验记录**。此前 alternating64-220 上的微弱正信号不能覆盖 synthetic 上的回退。v729 按中性处理；v728 回退、不推进；v730 与 v727 在已测同批次中同中位数，未证明进一步收益，且没有本次 synthetic 结果。这里没有新的 OJ 成绩，也不据此预报 OJ 提升。

## 设计与冻结源码

四个实验都只改变 E32 Stage1，其他 shape 路径、Stage2、数学/累加顺序、GIU 当前 K 的 global copies、pass、layout、raw/padded offset 语义保持相应基线。均为单 Ashared + 单 Bshared，总 32 KiB；没有 async、BSM、跨 K 预取、外部计算 kernel 或历史结果复用。

| 版本 | 基底与唯一设计差异 | 每 K64 的逻辑 A / B 读取次数 |
| --- | --- | --- |
| [v727](../../probe_v727_v720_e32_stage1_gate_b4_interleave.py) | 以 v720 为行为基线，沿用 v724 emitter 几何；保存 Gate B0..3，CTA 同步后用 Up 覆写同一 Bshared；每个 K16 读取一次 A、一次 Up B，再依次执行 Gate/Up MMA | 4 / 8 |

| [v729](../../probe_v729_v724_e32_stage1_early_tail_barrier.py) | 独立基于 v724 四 A 复用版本；仅把 steady 末尾同步移动到最后一次 Up B3 读取之后、最后一次 Up MMA 之前；terminal 不变 | 4 / 8 |

## CPU、生成源码与随机精度的检查边界

### CPU / 源码检查

- [v727/v728 自包含审计](../v727_v728/audit_v727_v728_cpu.py)：所有 v720 原 builder 与其他 host 路径完整源码一致，仅 E32 分派新 builder；相对 v724 emitter builder 只允许 operand fragment 分配与微调度变化。逐 K 标记数据流覆盖 `k_steps=1,2,3,4,31,32,111,112,113`，检查每个 C 的完整 K16 序列、保留 Gate B 不被 Up 覆写、shared 覆写保护及逻辑索引覆盖。
- [v729 精确移动审计](audit_v729_cpu.py)：整个模块 AST / 可执行源码仅移动一个既有同步语句，terminal、dispatcher、cache、pass 和所有其他路径不变；尾部剩余 MMA 只使用私有片段。此脚本是精确源码审计，不额外宣称其执行了新一轮 host mock。
- [v730 自包含审计](../v730/audit_v730_cpu.py)：整个模块仅 header 与一次同步移动不同；terminal 原样，移动后只有两次私有 fragment MMA，没有后续 shared 读取；逐 K 数据流检查通过。
- v727/v728/v730 的 host mock 覆盖 E1/E8/E16/E32/E64、FP16/FP32 route dtype、每组两次新输入；每次完整 entry 启动两次 kernel，当前输入参数正确转发。该检查不执行 GPU 数值计算。
- 四个 probe 均通过 Python 语法与 Ruff 检查。CPU 审计不会证明编译器自动插入同步、真实硬件寄存器分配或 GPU 性能。

### GPU 随机精度：已测与未测

前三批使用本地 E32 / H7168 / I2048，routing 为 `alternating64-220`，raw=4544、padded=6144、48 个 M blocks；它不是已核实的 OJ 输入分布。输入和三组权重为 FP16 随机数，route weights 为 FP32，输出为 FP16。当前 [remote_stage_ab.py](../../remote_stage_ab.py) 的该路径使用固定 seed `20260901 + case2 = 20260903`，每个进程只构造一次随机输入。第四批改用 `synthetic` routing，padded=6912、54 个 M blocks，详见下文单独结果；不与前三批混算。

前三批每批候选都进行了 3 次 correctness repeat，分别执行 `launch_full` 和真实 `run_kernel` 两条完整路径；每次路径检查前 workspace/output 用 NaN 填充，输出检查同时拒绝非有限值。前三批所有已列候选均报告 `max_abs=0.000000, bad=0/44040192`，与该批 v720 参考输出完全相同。第四批的参考改为留存的 v432 输出，检查规模与结果见该批记录。

这是“固定随机输入、重复执行并重新 NaN 填充”，不是三个独立随机种子，也不是输入本身含 NaN 的健壮性测试。`alternating64-220` 路径的参考是候选 c0=v720 当次重新计算的输出，不是独立数学参考；因此只能证明这些样本上与 v720 一致。CPU 的 route FP16/FP32 覆盖也不能替代未执行的 GPU dtype/shape 组合。其他 shape 路径通过源码保持不变，本批没有给它们新增 GPU 数值或 OJ 证明。

## 计时方法与完整样本

以下各批均无 tracer，`stage=entry`，一次 warmup、每轮一次计时调用、4 轮 forward/reverse/forward/reverse。每次 entry 仍包含 Stage1 + Stage2 两次 kernel launch。NaN 填充与 correctness 检查在正式计时外；表中是 event 计时的完整 entry，不是 Stage1 单独耗时。

所有样本按 round1..4 排列，不删除离群值，不把不同批次混算。配对差值定义为同一轮 `candidate - c0`，单位 µs，负数更快；“配对差中位数”不等于“各自中位数之差”。同轮配对是减少漂移影响的比较方式，不是同时运行或统计显著性证明。

## 下一步使用方式

- v727 不具跨 fixture 稳健收益，不优先提交 OJ，仅保留结构实验记录；不能把首批约 36 µs 的中位差当作已稳定复现的收益或忽略第四批负向结果。
- v728 在本地初筛中较慢，当前回退/关闭推进；这不是声称所有输入、所有设备都必然更慢。
- v729 按中性记录，不合并为必然优化。
- v730 作为 v727 的一次同步位置消融保留，目前不升级为优于 v727 的新基线。
- 后续如追加 profiling，应明确输入模式、是否带 tracer、资源字段来源与单位；不要把此处的静态数组/同步位置数当作硬件计数器，也不要将 trace 与无 trace 时间直接混算。
- OJ 的分数/用时只能来自对应提交实际反馈。当前这些本地实验不替换已确认的 OJ 基线，不预报分数。
